- **Consequence →** The weekly percent can exceed 100% (8 entries gives 114) while the streak stays at 1, so report and export disagree with reality.

### COR-3 · correctness: non-atomic, unlocked writes can lose data
- **Cause →** `save_habits` opens the real file with `"w"`, which truncates it immediately (`storage.py:19`), and then streams JSON into it (`storage.py:20`). Every command also does load, modify, save with no lock (`cli.py:30,34,40`).
- **Event →** The process is interrupted (Ctrl-C, kill, disk full) between truncation and the end of the dump, or two commands run at once.
- **Consequence →** The file ends up empty or partial, which triggers COR-2. With concurrent runs, one update silently overwrites the other. The `data/` folder is git-ignored, so there is no backup.
- **Where:** `storage.py` `save_habits` (17-20), `cli.py` (30-40)
- **Verify** (simulates an interrupted dump):
  ```
  python - <<'EOF'
  import os, tempfile
  from unittest import mock
  from habit_tracker import storage
  from habit_tracker.models import Habit
  p = os.path.join(tempfile.mkdtemp(), "h.json")
  storage.save_habits([Habit("a", "2026-11-21")], p)
  with mock.patch("json.dump", side_effect=KeyboardInterrupt):
      try: storage.save_habits([Habit("a", "2026-11-21")], p)
      except KeyboardInterrupt: pass
  print(repr(open(p).read()))
  EOF
  ```
  Expected from reading: `''` (not executed).
- **Confidence:** medium. Truncate-on-open is seen. The timing of a real interruption is inference. The concurrent-run case is a guess, and docs/01 §4 lists "single user" as an unchecked assumption.

### COR-4 · correctness: export file I/O is not cross-platform
- **Cause →** `export --out` uses `open(args.out, "w")` with no `encoding` and no `newline` (`cli.py:51-52`). The CSV text already contains `\r\n` from the csv module (`exporter.py:28-32`).
- **Event →** Someone exports on Windows (which the author uses, per docs/01), or with a non-ASCII habit name.
- **Consequence →** On Windows each row ends in `\r\r\n` (blank lines in some tools). A name that the locale code page can't encode (for example Cyrillic under cp1252) can raise `UnicodeEncodeError` after the user has already checked in.
- **Where:** `cli.py` export branch (49-53), `exporter.py` `to_csv` (27-32)
- **Verify** (Windows scratch copy, PowerShell):
  ```
  python -m habit_tracker.cli add Read
  python -m habit_tracker.cli export --format csv --out out.csv
  python -c "print(open('out.csv','rb').read())"
  ```
  Expected from reading: `\r\r\n` on Windows, `\r\n` on Linux (not executed). Also try `add "Чтение"` with a cp1252 code page.
- **Confidence:** medium. The `open()` calls are seen. The platform behaviour comes from Python semantics and is not executed. The encoding failure depends on locale.

### SEC-1 · security: `export --out` can overwrite any file, including the data store
- **Cause →** `--out` is passed straight to `open(..., "w")` with no path check, overwrite protection or confirmation (`cli.py:50-52`).
- **Event →** A user, script or AI agent passes a path like `data/habits.json`, or any existing file.
- **Consequence →** The file is silently replaced. If it is the store, CSV content in it triggers COR-2 and the habits are lost. The attack surface is small, since it is a local single-user CLI.
- **Where:** `cli.py` `main`, export branch (48-55)
- **Verify** (scratch copy):
  ```
  python -m habit_tracker.cli add Read && python -m habit_tracker.cli export --format csv --out data/habits.json && python -m habit_tracker.cli report
  ```
  Expected from reading: the export succeeds, then `report` crashes with `JSONDecodeError` (not executed).
- **Confidence:** high that no guard exists (seen). Medium on real-world impact.

### SEC-2 · security: CSV formula injection through habit names
- **Cause →** `to_csv` writes names verbatim (`exporter.py:14,27-32`), and `add` accepts any string (`cli.py:14`, `tracker.py:13-19`).
- **Event →** A habit named like `=1+1` or `@SUM(...)` is exported and the CSV is opened in Excel or Sheets.
- **Consequence →** The cell is evaluated as a formula. This only matters if the names or `habits.json` come from someone else, so severity is low for single-user use.
- **Where:** `exporter.py` `_rows` (10-20), `to_csv` (27-32)
- **Verify** (in memory):
  ```
  python -c "from habit_tracker.exporter import export; from habit_tracker.models import Habit; print(export([Habit('=1+1','2026-11-21')], 'csv'))"
  ```
  Expected from reading: a data line starting with an unquoted `=1+1,2026-11-21,0,0` (not executed).
- **Confidence:** medium. The unescaped write is seen. Impact depends on how the CSV is used.
